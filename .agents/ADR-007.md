# ADR-007: Dependency-Free CSV/XLSX Import Into Existing Badge Rows

Status: Accepted for Task 7.

## Context

Badge Generator already accepts validated `BadgeDataRow` values. Task 7 requires CSV and XLSX input without creating a second generation pipeline or adding Excel COM automation.

## Decision

Add pure import sources in `CorelMate.Badges`:

- `CsvImportSource` parses quoted CSV records, escaped quotes, multiline fields, UTF-8, CRLF, and LF.
- `XlsxImportSource` reads the first worksheet directly from the XLSX ZIP/XML package without requiring Excel.
- `BadgeImportMapper` normalizes headers, detects duplicates, maps detected CorelMate variables, accepts `QUANTITY`/`QTY`, ignores blank rows, reports extra columns, and validates every row before producing existing `BadgeDataRow` values.

The WPF Docker selects the file, displays import/mapping status, and replaces the existing manual row editors with normalized rows. CorelDRAW is not used during parsing or validation.

## Alternatives

- Microsoft Office interop: rejected because Excel would be required and COM automation is outside scope.
- A third-party CSV/XLSX dependency: rejected because the existing BCL provides the required ZIP/XML primitives and the CSV grammar is covered by focused tests.
- A second import-specific generation pipeline: rejected because it would duplicate Badge Generator behavior.

## Consequences

The release package has no new external dependency. XLSX support currently uses the first worksheet. Formula recalculation, macros, charts, merged-cell semantics, and advanced Excel formatting are outside scope. Imported personal data remains in memory only and is not uploaded or persisted.

## Verification

Synthetic tests cover quoted CSV, escaped quotes, Unicode, duplicate headers, invalid quantities, empty required values, extra columns, XLSX first-worksheet reading, and normalized rows. Real foreground file-picker/import interaction remains unverified.
